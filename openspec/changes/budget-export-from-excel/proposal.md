## Why

Every organization on the platform tracks its budget in its own Excel layout before ever touching GrantFlow. Today the only way in is manual line-by-line entry (or the chat free-text parser, which requires typing a description rather than reusing a file the org already has). Letting an org drop its existing spreadsheet and get a populated draft budget removes the single biggest friction point in onboarding a new budget, without forcing the org to redo work by hand-mapping their columns to ours first.

## What Changes

- Add `POST /budgets/import-excel` (budget service): accepts an uploaded `.xlsx` file, extracts budget lines from it, and creates the budget via the existing `create_budget_with_lines_service` in `ai_draft` status — same landing status the chat parser already uses, so the existing confirm/edit UI (`budget-confirmation-ui`) is reused as the review step. No new "confirm this mapping" wizard.
- Extraction is **AI-first**, not a header-matching cascade: a cleaned dump of the sheet is sent to a structured-output AI call that returns category/description/amount/currency per line directly. This replaces the earlier plan to revive `mapping_service.py`'s rule-based/embedding column-header matching — testing the existing dormant pipeline against a real donor spreadsheet already in the repo showed it drops **100% of line items** (its per-row formula filter discards any row containing a formula in *any* column, which is nearly every row in a realistic template with a computed second-currency column). Hardening that approach for every donor's layout isn't tractable; one AI call handles arbitrary real-world layouts without per-template code.
- AI extraction is **BYOK-preferred with a GrantFlow-funded cheap-model fallback**: uses the org's own provider key when configured (`ai-provider-settings`), and falls back to a GrantFlow-funded low-cost model when no key is configured, so import quality never depends on whether the org has set up AI. This is a deliberate, scoped carve-out from the platform's existing BYOK-only/no-fallback policy, decided specifically for this feature. Every AI call is audit-logged with funding source, token count, and cost, and platform-funded calls are rate-limited per organization.
- Anything the AI extraction can't confidently resolve is still imported — the raw label/value lands in the budget line's `extra_fields` rather than being dropped, so the user fixes it in the normal edit UI instead of being interrupted mid-upload.
- Revive and harden `ExcelStructureDetector` (`spreadsheet_reader.py`) as the sheet-cleaning step feeding the AI call (fixing its formula-row-drop bug: exclude formula cells individually, not their whole row); retire the experimental, unused `detector.py` after porting its total/grand-total row heuristics.
- `DonorTemplateModel` (from `mapping.py`) becomes a shared, named, donor-scoped template identity — extended with a `fingerprint` (normalized header sequence) and `detected_structure` (the AI-derived extraction mapping) and a `version` field reserved for future use. A fingerprint match is looked up **globally**, not per-organization, so a second org uploading the same donor's file gets the free/fast path (skip AI, extract directly from the stored structure) even on their first-ever upload. `BudgetModel.donor_template_id` — an existing, currently-unused FK — becomes the provenance link from a budget back to the template it was imported from. Saving a newly-extracted layout as a reusable template is an optional, non-blocking prompt after a clean confirm, not a requirement.
- **Retire the now-superseded parts of the dormant donor-mapping subsystem** rather than leaving a second orphaned layer behind: delete `mapping_service.py`'s rule/embedding matching code, the `mapping_routes.py` endpoints built around it (`/suggest`, `/mappings`, `/fields`, the debug `/ping`), `mapping_crud.py`'s field-mapping CRUD, and the `DonorFieldModel`/`NgoMappingModel`/`SemanticFieldMappingModel`/`UploadedTemplateModel`/`TemplateToBudgetMappingModel` models and their (currently empty, unused) database tables. Remove the `sentence-transformers`/`torch` dependencies they existed to support — nothing will call them once this ships, so the "already paid for" reasoning no longer applies, and removing them shrinks the budget-service image by roughly 1–2GB.
- Wire `budget-export-from-excel` routes into all three gateway configs (`nginx-dev.conf`, `nginx.conf`, `Caddyfile`) and add a frontend upload entry point (button + file picker) on the budget list view.
- **Explicitly out of scope**: exporting a budget back into a donor's exact Excel layout (round-trip / cross-donor-template export). That's a real, larger feature — regenerating a formatted `.xlsx` file, not just reading one — and is deferred to a follow-on change once this import path is live. This change lays the groundwork for it (named, versioned template identity; provenance link) without building the regeneration engine itself.

## Capabilities

### New Capabilities
- `budget-excel-import`: uploading an org's Excel budget file and getting back a populated `ai_draft` budget with lines, via AI-first extraction that's shared and reused across organizations once a donor's template layout is recognized.

### Modified Capabilities
(none — `budget-confirmation-ui`'s existing draft-review/confirm flow is reused unchanged as the landing point for imported budgets)

## Impact

- **Affected code**: `services/budget/app/services/template_detection/` (revived + hardened), `app/models/mapping.py` (`DonorTemplateModel` extended and kept; `DonorFieldModel`/`NgoMappingModel`/`SemanticFieldMappingModel` deleted), `app/models/budget_templates.py` (deleted — `UploadedTemplateModel`/`TemplateToBudgetMappingModel` no longer needed), `app/services/mapping_service.py` (deleted), `app/api/mapping_routes.py` (most endpoints deleted; `DonorTemplateModel` CRUD kept/adapted), `app/crud/mapping_crud.py` (field-mapping functions deleted), `app/schemas/mapping_schema.py` (field/mapping/suggestion schemas deleted).
- **Dependency surface**: removes `sentence-transformers`/`torch` (and `redis` if nothing else in the budget service needs it) from `requirements.txt` — net reduction in deployment weight, not the "already paid for, keep it" reasoning from the earlier draft of this proposal.
- **AI service**: new capability for full-sheet structured extraction (category/description/amount/currency per line), following `parse_service.py`'s PydanticAI pattern but BYOK-preferred with a platform-funded fallback rather than strictly BYOK-only; adds cost-tagged audit logging and per-organization rate limiting for the platform-funded path.
- **Frontend**: new upload entry point on the budget list; no new review/mapping UI (reuses the existing single-budget draft view); a lightweight optional "save as reusable template" prompt after a clean confirm.
- **Gateway**: new route added to `nginx-dev.conf`, `nginx.conf`, and `Caddyfile`.
- **DB**: migration extends `donor_templates` with `fingerprint`/`detected_structure`/`version`; a separate migration drops the now-dead `donor_fields`, `ngo_mappings`, `semantic_field_mappings`, `uploaded_templates`, `template_budget_mappings` tables (verified empty/unused in all environments).
- **Deferred**: export/round-trip regeneration into a donor's exact Excel layout is a follow-on change, not part of this one.
